Verification — what was checked, when, and with what result

This site is only as good as its audit trail. Every listing URL was opened and compared with the dataset; the rows that could not be re-read are labelled prior capture rather than presented as fresh. The security check is re-runnable by anyone: python3 scripts/verify.py.

Run this after every review

python3 scripts/verify.py — fails the build if any value lacks a source, if a derived number does not recompute from raw inputs, if a blank cell is not flagged, or if a dollar amount in the generated HTML cannot be traced to the dataset. It also runs negative tests: injected fake prices, fake weights and hand-typed figures must all be caught. The second checker, python3 tools/check_hallucinations.py, audits the preserved docs/ archive the same way.

What is still not verified — by design

  • Purity by assay. No seller supplied an XRF or fire-assay result for the specific ring. Every karat value here is the seller's claim, read from the listing.
  • Physical weight. Published weights are claims; we did not weigh anything.
  • Hallmark + maker's mark. Not shown in any listing, so the column is blank on every row.
  • Independent reputation for Etsy shops. Etsy's own ratings are not independent. No third-party data was verified, so none is shown.

Method, in one paragraph

A value enters the dataset only after it is read on the official page (or, where explicitly labelled, a search snippet of that page), with the URL and the date recorded next to it. Derived values are computed by script and recomputed by the checker. Anything unconfirmable is left blank, given a flag that links the page where it was looked for, and published on Flagged for review. No value is estimated, interpolated, or carried over from a similar product.
